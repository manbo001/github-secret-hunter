# 敏感信息监测聚合平台

在自有资产和授权范围内，持续监测代码托管平台上泄露的 Access Key、Token、密码等敏感信息。

同一套关键词，同时跑 GitHub 代码搜索和 Gitee、GitCode 的仓库线索搜索，结果统一入库、去重、告警。单机部署，一个 PHP 站点加一个 MySQL 就能跑，后台任务随页面请求触发，不需要 Cron，也不需要消息队列。

## 功能

### 多平台聚合搜索

- **任务下发**：一套关键词同时检索 GitHub（代码级，支持 `filename:`、`extension:` 等限定符与命中片段）、Gitee、GitCode（仓库线索级，匹配仓库名与描述）
- **后台分页抓取**：任务提交即返回，抓取在响应后进行，翻页间隔自动遵守平台限速，被限流时按平台建议时间退避
- **令牌负载均衡**：同一用户配置多个 GitHub Token 时按"最久未用"轮转，翻页速度等效叠加各令牌的搜索配额；限流配额按令牌独立计算
- **大查询自动拆分**：GitHub / Gitee 单次查询只能拿前 1000 条结果，命中超限后自动按 `language` 切分子查询、超大的切片再按文件 `size` 八等分细分，最多可覆盖数千条结果（实测同一关键词从 840 条提升到 3400+ 条唯一命中）
- **自动复查**：任务完成后按可配置间隔复查，只把新增结果入库并推送，存量不重复告警

### 仓库更新监控

- 对指定仓库定期拉取提交，两次检查间的多次提交全部捕获，发现新提交即入库并按需推送
- 平台不一致的令牌自动校验，令牌失效支持在监控列表直接换绑并立即重查

### 推送通知

- 钉钉、企业微信、飞书、SMTP 邮件四类渠道；搜索告警与仓库监控模板分开自定义
- **令牌失效告警**：任一渠道收到平台 401 即推送固定格式的失效告警，指明失效令牌与影响范围，6 小时冷却防轰炸，渠道全失败时下轮自动重试
- **服务器资源告警**：CPU / 内存 / 磁盘使用率阈值可配（0 = 关闭），磁盘支持全部分区或指定分区；每 5 分钟检查，触发后 30 分钟冷却

### 令牌生命周期管理

- **删除有预告**：删除令牌前确认框列出关联的仓库监控与进行中的搜索任务，影响面一目了然
- **失败可自愈**：删除令牌导致失败的搜索任务，在重新添加同平台令牌时自动复活并换绑到新令牌；悬空的仓库监控同样自动换绑并立即重查
- **手动有兜底**：失败任务一键「重试」，绑定令牌已悬空时自动改绑到该平台最新令牌；监控页支持随时手动换绑
- **失效有指引**：监控报令牌错误时，页内直接给出下一步操作（换绑或先去添加令牌）

### 服务器资源监测（总览页）

- 仪表盘实时展示 CPU 使用率、内存占用、各磁盘分区用量、网络上下行速率与累计流量、CPU 型号、核心数、负载与运行时长
- 每 5 秒自动刷新，进度条按水位变色（绿 / 黄 / 红）
- 纯 PHP 读取 `/proc` 实现，无 shell 调用、无额外依赖

### 其他

- **任务结果导出**：CSV / Excel / JSON，自动处理 CSV 公式注入
- **数据保留期**：按天自动清理过期任务与结果，无需 Cron
- **站点自定义**：主副标题、网站图标（PNG / JPG / ICO / WebP）后台可视化配置，浏览器标签页同步
- **账号安全**：登录防爆破锁定、会话不活动超时可配、改密后其他会话自动失效、部署期可用 `.env` 指定管理员用户名
- **亮暗主题**：跟随系统或手动切换，全站适配

## 环境要求

- PHP 8.2+（php-fpm，需 pdo_mysql、curl、openssl、mbstring）
- MySQL 5.7+ / MariaDB 10.3+
- nginx 或 Apache（支持 SamWaf 等反代）
- Linux 服务器（服务器资源监测依赖 `/proc`，其余功能不限）

三个平台中至少有一个有效 Token 才能发起对应平台的搜索。

## 快速开始

```bash
git clone https://github.com/<你的用户名>/github-secret-hunter.git
cd github-secret-hunter

# 1. 配置环境变量
cp .env.example .env
vi .env    # 至少填 DB_USER / DB_PASS / APP_ENCRYPTION_KEY，可顺带配置 ADMIN_USER

# 2. 建库并导入表结构
mysql -u root -p -e "CREATE DATABASE github_secret_hunter CHARACTER SET utf8mb4;"
mysql -u root -p github_secret_hunter < sql/schema.sql

# 3. 权限与服务
chown -R www-data:www-data .
chmod 640 .env
systemctl restart php-fpm nginx
```

浏览器访问站点，用 `admin`（或 `.env` 中 `ADMIN_USER` 指定的用户名）/ `Admin@123456` 登录，首次登录强制修改密码。

详细步骤、常见坑（PHP-FPM 运行身份、时区、反代配置）见 [DEPLOY.md](DEPLOY.md)、[DEPLOY_CLOUD.md](DEPLOY_CLOUD.md)。

## 常用配置（.env）

| 配置项 | 说明 | 默认 |
|---|---|---|
| `APP_ENCRYPTION_KEY` | AES-256 密钥，加密存储平台 Token，更换后旧数据不可解密 | 必填 |
| `ADMIN_USER` | 部署时指定初始管理员用户名，替代默认 admin | admin |
| `APP_TIMEZONE` | PHP 时区，需与 MySQL 一致，否则日期统计错位 | Asia/Shanghai |
| `GITHUB_SEARCH_INTERVAL` | 翻页请求最小间隔（秒），过小会触发平台限流 | 7 |
| `RECHECK_INTERVAL_MINUTES` | 任务完成后自动复查新增的间隔（分钟），0 关闭 | 30 |
| `SSRF_ALLOWED_HOSTS` | 出站请求域名白名单（平台 API 与通知渠道域名） | 平台 + 常用通知域名 |

部署后的运行时配置（告警阈值、数据保留期、会话超时、GitHub 代理、站点标题图标等）在「系统设置」页面修改，优先级高于 .env。

## 架构与安全设计

- **后台任务**：页面响应后执行（`fastcgi_finish_request`），任务认领用条件 UPDATE 原子占位，并发请求不会重复抓取
- **全站防御**：预处理语句、输出统一转义、CSRF 全覆盖、SSRF 出站白名单、输入类型容错
- **密钥管理**：平台 Token 与通知配置 AES-256-GCM 加密入库，密码 bcrypt(cost=12)，日志中的认证凭据自动脱敏
- **通知可靠性**：渠道级失败隔离与日志留痕，冷却标记在成功送达后写入，避免告警被静默吞掉

## 目录结构

```
├── config/          # 应用与数据库配置（从 .env 读取，不硬编码密钥）
├── includes/        # 核心类：认证、安全、平台适配器、任务执行器、资源监测、通知
├── public/          # Web 入口页面、状态 API、静态资源、favicon 端点
├── sql/schema.sql   # 全量建表脚本（含默认数据与初始管理员）
└── DEPLOY*.md       # 部署文档
```
